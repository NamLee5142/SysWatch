# Sprint 5 — Database Integration

**Goal:** persist collected snapshots instead of keeping everything only in memory.

```text
C++ Agent  ->  Python Backend  ->  Database
 collects       owns persistence    SQLite
```

## Starting point

- The agent keeps exactly one snapshot in memory (`SnapshotRepository` holds a
  `std::optional<Snapshot>`, overwritten every collection cycle).
- The backend is pull-on-demand: `GET /snapshot` builds an `AgentClient`,
  fetches, validates, returns. Nothing is stored.
- There is no database dependency, model, or migration in the project.

Two things the sprint must add before persistence means anything: a **time
dimension** (a snapshot with no `collectedAt` cannot form a history) and a
**background poller** (nothing pulls from the agent unless an HTTP client asks).

## Locked decisions

| Decision | Final choice | Rationale |
| --- | --- | --- |
| Who stamps time? | **C++ Agent** | Timestamp represents collection time, not backend polling time. |
| Timestamp location | `Snapshot` | The timestamp travels with the collected snapshot through the existing Agent → Backend pipeline. |
| Database | **SQLite** | Zero infrastructure and ideal for the current single-machine Windows deployment. |
| ORM | **SQLAlchemy 2.x** | Clean repository abstraction and easier future PostgreSQL migration. |
| Migrations | **Alembic** | Proper schema evolution instead of manually modifying the database. |
| Schema | **One `snapshots` table** | Simple for Phase 1; avoids premature host normalization. |
| Host identification | `host_name` in `snapshots` | Useful for history queries without introducing a `hosts` table yet. |
| Host index | **Yes** | Supports future multi-host/history queries. |
| Keep `GET /snapshot` | **Yes, unchanged** | Existing live-monitoring API remains backward compatible. |
| Historical API | New `/snapshots` routes | Separates live data from persisted history. |
| Persistence location | Python Backend | The Agent remains responsible for collecting data; Backend owns persistence. |

## Schema

Table `snapshots`:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | integer PK | |
| `host_name` | text | From `systemInfo.hostName` |
| `collected_at` | datetime (UTC) | Stamped by the agent |
| `cpu_core_count` | integer | |
| `cpu_usage_percent` | float | |
| `mem_total_mb` | integer | |
| `mem_used_mb` | integer | |
| `disk_total_gb` | integer | |
| `disk_free_gb` | integer | |
| `os_name` | text | |
| `os_version` | text | |

- Index on `(host_name, collected_at DESC)` — serves both history queries and
  "latest per host".
- Unique constraint on `(host_name, collected_at)` — this is what makes the
  poller idempotent when it ticks faster than the agent's `collectionInterval`.

OS name and version are stored per row rather than normalized into a `hosts`
table: a host's OS version genuinely changes over time, so it is a property of
the snapshot. A `hosts` table belongs with Phase 2 agent registration.

## Commit plan

### Phase A — Agent: give snapshots an identity in time

**1. `feat(agent): add collectedAt timestamp to Snapshot`**
`Snapshot.h` gains `std::chrono::system_clock::time_point collectedAt`;
`SnapshotCollector::collect()` stamps it.
*Done when:* the existing agent test suite still passes.

**2. `feat(agent): serialize collectedAt in snapshot JSON`**
`snapshotToJson()` in `HTTPServer.cpp` emits `"collectedAt":"2026-08-12T11:15:27Z"`
(UTC, second precision).
*Done when:* `http_server_snapshot_tests` asserts the field is present and parseable.

**3. `fix(agent): run until interrupted instead of exiting after 5 seconds`**
`main.cpp` sleeps 5 seconds then shuts down — a poller cannot be tested end to
end against a process that dies. Replace with a signal handler and a wait loop.
*Done when:* the agent serves `/snapshot` until Ctrl+C.

### Phase B — Persistence foundation

**4. `chore(backend): add sqlalchemy and alembic to requirements`**
Exact pins, matching the existing pinning discipline.

**5. `feat(backend): add database engine and session factory`**
New `app/db/session.py`: module-level engine, `sessionmaker`, `get_session()`
context manager.
*Watch out:* `get_settings()` is uncached and returns a fresh `Settings` on every
call — the engine must be created once at startup, never per request.

**6. `feat(backend): define SnapshotRecord ORM model`**
`app/db/models.py`, per the schema above, including the index and unique constraint.

**7. `feat(backend): add alembic baseline migration`**
`alembic init`, URL read from settings, autogenerated initial revision.
*Done when:* `alembic upgrade head` builds the schema on a clean database file.

**8. `feat(backend): add SnapshotStore persistence layer`**
`app/repositories/snapshot_store.py` — `save()`, `latest(host_name=None)`,
`query(host, since, until, limit, offset)`. Keeps SQLAlchemy out of the service
and API layers, mirroring how `AgentClient` isolates httpx.

### Phase C — Ingest

**9. `feat(backend): add collectedAt to the Snapshot API model`**
Pairs with commit 2.
*Compatibility:* ship it `Optional` for one release, or the backend answers 502 to
every payload from an un-upgraded agent.

**10. `feat(backend): persist snapshots on retrieval`**
`SnapshotService` takes an optional `SnapshotStore` and writes on a successful
fetch. Write failures are logged and swallowed — a database problem must not turn
a working `/snapshot` into a 503.

**11. `feat(backend): add background snapshot poller`**
The core of the sprint. An asyncio task started at app startup, looping every
`poll_interval_seconds`, calling the blocking client through
`anyio.to_thread.run_sync`, writing via `SnapshotStore`. Must reuse a single
`AgentClient`, log-and-continue when the agent is unreachable, and exit cleanly
on `CancelledError`.

**12. `refactor(backend): replace on_event with lifespan`**
`main.py` uses the deprecated `@app.on_event`. The lifespan owns engine creation,
poller start, and shutdown of both.
*Done when:* no deprecation warnings, and the poller is confirmed stopped after shutdown.

### Phase D — Query API

**13. `feat(backend): add GET /snapshots history endpoint`**
Query params `host`, `since`, `until`, `limit` (default 100, capped at 1000),
`offset`. Returns `{"items": [...], "count": n}`. `422` when `since > until`.

**14. `feat(backend): add GET /snapshots/latest served from the database`**
Answers from storage, so it keeps working while the agent is down — unlike
`/snapshot`. `404` when no rows exist.

### Phase E — Configuration, retention, quality

**15. `feat(backend): add database and poller settings`**

| Variable | Default |
| --- | --- |
| `SYSWATCH_DATABASE_URL` | `sqlite:///./syswatch.db` |
| `SYSWATCH_POLL_INTERVAL_SECONDS` | `10` |
| `SYSWATCH_POLLING_ENABLED` | `true` |
| `SYSWATCH_RETENTION_DAYS` | `30` |

**16. `feat(backend): prune snapshots past the retention window`**
Runs on the poller loop, hourly rather than per tick.

**17. `test: cover the persistence layer`**
`SnapshotStore` round-trip, unique-constraint dedup, `query` filtering and
pagination — against SQLite in a `tmp_path` fixture.
*The suite must never touch the real `syswatch.db`.*

**18. `test: cover the poller and history endpoints`**
Poller: writes on success, survives `AgentConnectionError`, cancels cleanly.
Endpoints: `respx` plus a seeded test database, matching the existing test style.

**19. `chore: ignore syswatch.db and local alembic state`**
`.gitignore` currently only covers Django's `db.sqlite3`.

**20. `docs: document database integration`**
Backend README gets the schema, new endpoints, new environment variables, and
migration instructions; root README ticks Phase 2 "Database integration".

## Out of scope, flagged

- **`cpuInfo.usagePercent` is a hardcoded `0.0`** placeholder in `CPUCollector`.
  This sprint will faithfully persist a column of zeros. Worth fixing in a
  collector sprint before anyone reads those charts.
- **`hosts` table / agent registration** — deferred to Phase 2.
- **PostgreSQL or a time-series database** — Phase 3. The `SnapshotStore`
  abstraction is what keeps that a configuration change rather than a rewrite.
